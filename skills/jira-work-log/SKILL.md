## Алгоритм работы: Списание времени (Worklogs)

Когда пользователь предоставляет таблицу или список для списания времени:

### Шаг 1: Анализ данных

1. Извлеки из таблицы: дату, ключ задачи, количество времени и описание (если есть).
2. Определи месяц и год из контекста (например, заголовок "Август" при текущей дате 2026 года).
3. Если в один день указано несколько записей для одной и той же задачи — создай для каждой отдельный ворклог с разным описанием.

### Шаг 2: Проверка списаний (опционально)

Если пользователь не запретил проверку, используй `jira_get_worklog` для каждой задачи за указанный день, чтобы избежать дубликатов.

### Шаг 3: Распределение времени и формат

Чтобы записи не перекрывали друг друга и выглядели естественно:

1. **Распредели время** в течение рабочего дня (например: первая задача в 09:00, вторая в 11:00, третья в 14:00 и т.д.).
2. **ВАЖНО**: Используй строго формат даты: `YYYY-MM-DDTHH:mm:ss.000+0300` (с миллисекундами и часовым поясом без двоеточия), иначе сервер Jira может вернуть "Внутренняя ошибка сервера".

### Шаг 4: Вызов инструмента

Для каждой записи вызови `jira_add_worklog`:

- `issue_key`: Ключ задачи.
- `time_spent`: Время в формате Jira (например, "1h 30m", "8h", "30m").
- `started`: Рассчитанное время в формате `+0300`.
- `comment`: Описание из таблицы (если отсутствует, оставь пустым).

## Особенности

- **Язык**: сохраняй оригинальные названия статусов и приоритетов.
- **Лимиты**: при большом количестве списаний (более 15-20) выполняй их блоками, чтобы избежать таймаутов.
- **Конфиденциальность**: работай только с задачами, где пользователь является исполнителем или имеет права на запись логов.

## Примеры вызовов

### Списание времени

```python
mcp__mcp-atlassian__jira_add_worklog(
    issue_key="DDS-4386",
    time_spent="8h",
    started="2026-08-03T09:00:00.000+0300",
    comment="доработка mcp для передачи документа"
)
```

## Частые ошибки

1. **Неверный формат даты** — использование `+03:00` вместо `+0300` приводит к ошибке сервера.
2. **Наложение времени** — создание нескольких записей на одно и то же время (09:00).
3. **Игнорирование дублей** — объединение двух записей по одной задаче в одну, если у них разные описания.
