# Subagent Management

## Overview

**Сабагент** — это индивидуальный инструмент (в `list_tools` имеет
`type: tool`), который самостоятельно выполняет целую подзадачу
(поиск, исследование, проверка, анализ) и возвращает готовый результат:
отчёт, выводы, список замечаний.

Ключевые отличия от tool group:

| Свойство                | Поведение                                                    |
| ----------------------- | ------------------------------------------------------------ |
| Тип в `list_tools`      | `type: tool` (не `group`), списка `tools:` нет               |
| Включение               | `enable_tool("<имя>")` — ровно так же, как для групп         |
| Отключение              | **невозможно** — `disable_tool` вернёт успех, но инструмент останется включённым |
| Когда callable          | Только на **следующем** ходу после включения                 |
| Контекст                | Сабагент видит историю чата, пересказывать весь контекст не нужно |

## When to use

Делегируй подзадачу сабагенту, если:

- нужен **внешний источник** данных (веб-поиск, актуальная информация,
  справочные материалы) — у базовых инструментов чата его нет;
- задача объёмная и **многошаговая**, но результат нужен целиком и
  самодостаточный (отчёт с выводами и источниками);
- нужен **второй взгляд** на код или решение (ревью, поиск ошибок).

Не используй сабагентов для простых локальных действий (поиск по файлам,
чтение/правка кода, git) — для них есть обычные инструменты, они быстрее.

Если подходит несколько сабагентов — бери **узкоспециализированный**;
общий/универсальный сабагент — только когда ни один специализированный
не покрывает задачу.

## Workflow

1. **Discover.** Вызвать `list_tools` и найти кандидатов: это
   индивидуальные инструменты, по `description` которых видно, что они —
   сабагенты (выполняют подзадачу и возвращают отчёт).
2. **Decide.** Сравнить `description` кандидатов с текущей задачей и
   выбрать подходящий по принципу наименьшего охвата.
3. **Enable.** `enable_tool("<имя>")` с точным именем из `list_tools`.
4. **Act (на следующем ходу).** Вызвать сабагента с параметрами согласно
   его JSON-схеме (обязателен `task` — полное описание подзадачи;
   дополнительные опциональные параметры — если схема их объявляет).

Никогда не угадывать имя и не вызывать инструмент, которого нет
в `list_tools`. Если уже `attached: true` — включение не нужно,
можно вызывать сразу.

## Quality of `task`

Качество результата определяется качеством задачи. В `task` обязательно:

- **что** найти/проверить/сделать (конкретно, без «всё про ...»);
- **контекст**, если задача неоднозначна (период, объект, язык, версия);
- **формат результата** (таблица, проценты, список замечаний, источники);
- **критерии достаточности** (сколько источников, какие ограничения,
  что считать «готово»).

Сабагент видит историю чата — пересказывать обсуждение не нужно, но
формулировка самой подзадачи должна быть самодостаточной.

## Scenarios

### Делегировать подзадачу

```
→ list_tools()                  → найти сабагентов по type/description
→ enable_tool("<имя>")          → включить подходящий
→ (следующий ход) <сабагент>(task = "...")   → выполнить подзадачу
→ передать пользователю результат: выводы + источники/замечания
```

### Обработать ответ сабагента

- Передать пользователю **цифры и факты с источниками**, а не «сабагент
  сказал, что...»;
- если результат противоречивый или неполный — задать уточняющий `task`
  повторно (вызов можно повторять, инструмент уже включён);
- пометить предварительность данных, если сабагент так указал.

### Попытка отключить сабагента

Пользователь: «убери [сабагента] из чата»

```
→ disable_tool("<имя>")
→ вернёт успех, но инструмент ОСТАНЕТСЯ включённым
```

Сообщить: индивидуальные инструменты отключить нельзя, сабагент
останется доступен. Повторный вызов не делать.

## Constraints

1. **Сначала discovery.** `list_tools` до `enable_tool`; имена не гадать.
2. **Включать по необходимости.** Только тот сабагент, который нужен
   для текущей задачи, не «на всякий случай».
3. **Один ход — одно включение.** Вызов — только на следующем ходу после
   `enable_tool`.
4. **Не пере-включать.** `attached: true` — инструмент уже доступен.
5. **Отключение невозможно.** Не повторять `disable_tool` на
   индивидуальном инструменте.
6. **Локальное — локальными инструментами.** Сабагенты — для нетривиальных
   подзадач и внешних источников, а не замена `read_file`/`grep`.
7. **Самодостаточный `task`.** Конкретная цель + контекст + формат
   результата + критерий готовности.
8. **Ответ не цитировать слепо.** Проверять ключевые факты по источникам
   из отчёта; расхождения между источниками показывать пользователю.
